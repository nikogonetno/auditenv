# auditenv. RL-среда для ИИ-аудитора

Офлайн-среда для обучения и проверки ИИ-аудитора. Генератор создаёт вымышленную компанию за один месяц: счета, платежи, разнесения, курсы и книгу проводок. В книгу вносятся скрытые ошибки четырёх типов: дубль счёта поставщика, ошибка разнесения платежа, неверный курс и ошибка периода. Рядом лежат корректные двойники, похожие на ошибки. Агент расследует книгу узкими инструментами и сдаёт выводы с доказательствами. Оценщик сверяет их с эталоном строгим правилом.

Все данные синтетические.

## Статус

Чекпоинт 0 готов, идёт чекпоинт 1. Есть структура пакета, тесты golden-эпизода v0.1, `make verify`, Dockerfile и оценщик в `auditenv/grader/`: строгий matcher, F1 и награда организаторов. Оценщик повторяет все 19 чисел колонки STRICT из таблицы QA v0.1. Среды reset/step и политик ещё нет, они ждут текста §04 кейса. План чекпоинтов лежит в плане команды, контракт в [SPEC.md](SPEC.md).

## Быстрый старт

Нужен только Python 3.11 или новее, без установки пакетов.

```bash
make verify
```

В Docker, без сети:

```bash
make docker-verify
```

## Что проверяет `make verify` сейчас

1. Все модули пакета импортируются, runtime-зависимостей нет.
2. Golden пересобирается побайтно одинаково при `PYTHONHASHSEED` 0, 1 и 12345. Отдельный тест подтверждает, что сид действительно доходит до дочернего процесса.
3. Все 8 сумм эталона пересчитываются только из доказательств.
4. В открытых файлах нет закрытых слов, ID эталона и колонок с подчёркиванием.
5. ID уникальны между таблицами.
6. Детектор QA находит те же 8 ошибок. Шаг падает только на критичной находке.
7. Оценщик: все случаи таблицы QA (E-24), порядок выводов (E-26), ID с префиксом и без (E-27), неверный формат вывода (E-28), максимальное паросочетание, одинаковый результат при разных `PYTHONHASHSEED`, тесты повторной проверки QA (`tests/test_qa_recheck1.py`).
8. Разбор сообщений политики `auditenv.server.decode_message`: размер, NaN и Infinity, длинные целые и глубокая вложенность дают короткую ошибку, а не падение процесса (R-09).

Независимые скрипты QA для оценщика лежат в `qa/`. Их запускают вручную, в `make verify` они не входят, потому что мутационный прогон занимает около минуты:

```bash
python3 -I qa/qa_recheck_grader.py .
```

```bash
python3 -I qa/qa_attack_grader.py .
```

```bash
python3 -I qa/qa_mutate_grader.py .
```
