# CLAUDE.md

Правила для Claude Code в этом репозитории. Источник правды для схемы, контракта и оценки это `SPEC.md`. Если задача с ним расходится, остановись и спроси, а не придумывай.

## Проект

Офлайн RL-среда для ИИ-аудитора на Python 3.11. Генератор вымышленных компаний со скрытыми ошибками учёта, среда reset/step с узкими инструментами и строгий оценщик. Баллы жюри дают корректность контракта, данных, награды и воспроизводимость. UI, обучение и умный агент баллов не дают и не делаются.

## Команды

- `make verify` запускает всю проверку. Код попадает в main только после неё.
- `make test` запускает только unit-тесты, подробно.
- `make qa` запускает независимый детектор QA на golden-эпизоде.

## Жёсткие правила

- Только стандартная библиотека. Новая зависимость появляется только через PR, о котором знают оба.
- Детерминизм по `SPEC.md` §2. Случайность только из `random.Random(seed)`, деньги целыми минорными единицами, курсы через `Decimal` с `ROUND_HALF_UP`, вывод через `sorted` и `sort_keys`. Без `float` в деньгах, без `datetime.now()`, `hash()` и tzdata.
- В тестах детерминизма дочерний Python запускай с `-P -s`, а не с `-I`. `-I` игнорирует `PYTHONHASHSEED`.
- Ни один открытый файл, наблюдение, текст ошибки или `info` не содержит truth, provenance, issue_id, twin_id, названий типов ошибок и слов truth, provenance, inject, twin, scenario.
- Ответ «не найдено» одинаков для любого отсутствующего ID, включая закрытые.
- Только синтетические данные. Никаких реальных компаний, людей, счетов и ключей. Секреты в код не кладём.
- Не правь `tests/fixtures/`. Golden обновляет только A новой версией в отдельной папке.
- Тесты на matcher и награду пишутся раньше кода.

## Кто где работает

A отвечает за `auditenv/world.py`, `auditenv/inject/` и `auditenv/transform.py`. B отвечает за `auditenv/env.py`, `auditenv/grader/`, `auditenv/server.py`, `policies/`, `scripts/` и Docker. Общие файлы `SPEC.md`, `CLAUDE.md`, `README.md` и `Makefile` меняются только по договорённости. Верификатор пишет B независимо от инъекторов A, чтобы одна и та же ошибка не попала в оба места.
