## 1. Наборы эпизодов в `--config` и закрытый прогон набора (M4 и M1)

- `--config` принимает и файл набора вида `{version, split, episodes: [{seed, config}]}`, как `configs/dev_v2.json`.
  - С `--seed N` берётся config этого seed из набора. Seed не из набора даёт понятную ошибку со списком seed.
  - Без `--seed` прогоняются все эпизоды набора по очереди, в один файл траекторий и один журнал оценщика. Вывод это строка JSON на эпизод и строка итога (средняя награда, TP, FP, FN, P, R, F1, шаги).
  - Обычный config строкой или файлом работает как сейчас. `reset(seed, config)` и строгая проверка ключей не меняются, набор разбирает только CLI.
- Тест. `--config configs/dev_v2.json --seed 2000` даёт тот же `episode_id`, что `episodes/dev/index.json` для 2000. Набор из двух эпизодов даёт две строки и итог.
- В вывод прогона добавить версию кода и `config_sha256`, а для набора ещё `version` набора. Ключи траекторий не трогать, их ровно 7 по кейсу §09.
- README, абзац «Закрытый прогон жюри». Политика и файл набора в одной смонтированной папке только для чтения, журналы в отдельной папке, созданной `mkdir -m 700`. Примерно так.
  ```bash
  mkdir -m 700 jury_out
  docker run --rm --network none -v "$PWD/policy:/policy:ro" -v "$PWD/jury_out:/out" auditenv:dev python3 -m auditenv.run --policy-cmd "python3 /policy/my_policy.py" --config /policy/hidden_set.json --mode eval --sandbox required --trajectories /out/trajectories.jsonl --grader-log /out/grader_log.jsonl
  ```
  Сказать, что политика из нескольких файлов кладётся в ту же папку.
- CI. Шаг закрытого прогона гоняет набор из двух эпизодов этой командой и проверяет, что в `jury_out` есть траектории на оба эпизода и журнал оценщика, а политика от `auditpolicy` не может их прочитать. Последнее как тест в Docker.
