## Где работать

Ветка `a/generator` от свежего `main`. Пушить не реже раза в два часа, даже если не всё готово, чтобы PM и B видели прогресс. Свои файлы: `auditenv/generate.py`, `auditenv/world.py`, `auditenv/inject/`, `auditenv/transform.py`, `tests/test_generator.py`. Чужие файлы не трогать.

## Интерфейс, который ждёт B

```python
# auditenv/generate.py
def generate_episode(seed: int, config: dict, out_dir: str) -> None:
    """Пишет out_dir/public/{manifest.json, invoices.jsonl, payments.jsonl, ledger.csv, fx.csv, policy.json}
    и out_dir/private/{truth.json, provenance.json}. Детерминированно по (seed, config)."""
```

`config` приходит уже проверенным и с заполненными значениями по умолчанию из `auditenv/config.py` (его пишет B). Схема config v1:

```json
{
  "period": "2026-09",
  "base_currency": "KZT",
  "documents": [150, 200],
  "foreign_pct": [0, 60],
  "company_offsets": ["+03:00", "+04:00", "+05:00", "+06:00"],
  "errors": {"duplicate_invoice": 1, "payment_allocation": 1, "fx_rate": 1, "period_cutoff": 1},
  "scenarios": {"C1": 0, "C2": 0},
  "twins": [3, 8]
}
```

- `period` может быть `null`, тогда месяц 2026 года выбирает seed.
- Чистая компания это все `errors` и `scenarios` равны 0.
- C1 даёт 3 ошибки, C2 даёт 1. Всего ошибок не больше 12.
- Генератор сам создаёт условия для каждой запрошенной ошибки. При `fx_rate` в мире есть валютные документы, при C1 граница периода приходится на два рабочих дня с разными курсами. Если условие создать нельзя, `ValueError` с коротким текстом.

## Этапы и критерии готовности

### Этап 1. К субботе 02.00

- Чистый мир. Счета AR и AP, платежи полные, частями и частичные, валютные документы, строки 6250 и 7430, окно периода плюс 7 дней и не меньше 10 настоящих строк соседних периодов с каждой стороны, от 150 до 200 документов, не больше 2000 строк книги.
- Генератор сам проверяет INV-01…INV-16 до и после внесения ошибок и падает при нарушении.
- Ошибки `duplicate_invoice` (вариант same_vendor_ref_reformatted) и `payment_allocation` (вариант partial_allocation).
- Готово, когда эпизод из любого seed грузится `load_episode` и oracle получает 1.0:
  `python -m auditenv.run --policy oracle --mode train --episode-dir OUT`
- Готово, когда два запуска с одним seed и разным `PYTHONHASHSEED` дают одинаковые sha256 всех файлов, а генерация идёт быстрее 5 секунд.

### Этап 2. К субботе 12.00

- `fx_rate` (вариант rate_of_entry_date) и `period_cutoff` (вариант pulled_into_period, только документы в базовой валюте).
- Чистые компании.
- Каждая сумма ошибки больше двух допусков (INV-20), иначе берётся другой документ.
- Готово, когда на 50 seed подряд oracle получает 1.0 и верификатор V не находит проблем.

### Этап 3. К субботе 20.00

- Связанные сценарии C1 и C2 из `DOMAIN_SPEC_A.md`.
- Пять двойников. Ежемесячная подписка, оплата частями, документ в выходной, полночь по UTC, позднее внесение.
- `auditenv/transform.py`. `permute_and_rename(episode_dir, out_dir, salt)` переставляет строки и меняет все ID, а truth переходит в тот же truth с новыми ID и теми же суммами (INV-22).
- `provenance.json` с seed, версией генератора, sha256 config, списком изменений и двойниками.

## Жёсткие правила

- Только стандартная библиотека. Случайность только из `random.Random(seed)`. Деньги целыми минорными единицами, курсы через `Decimal` с `ROUND_HALF_UP`. Вывод через `sorted` и `sort_keys`. Без `float` в деньгах, без `datetime.now()`, `hash()` и tzdata.
- ID из 6 символов Crockford Base32, назначаются после внесения ошибок, уникальны между таблицами.
- В открытых файлах нет issue_id, названий типов ошибок и слов truth, provenance, inject, twin, scenario.
- Лишние варианты ошибок сверх перечисленных делаем только после этапа 3.
