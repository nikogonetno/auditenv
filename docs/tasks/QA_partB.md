## Правила

- Ты жюри, которое видит репозиторий впервые. Читать можно только README.md, DESIGN.md, SPEC.md, docs/CASE.md, docs/METRICS.md и вывод команд.
- **Не открывать** `auditenv/`, `policies/`, `examples/`, `tests/`, `scripts/`, `qa/`. Если без кода что-то не понять, это находка.
- Код не чинить. Находки идут в отчёт с важностью и командой повтора, PM передаст B.
- На машине нет Python 3.11 и Docker. Работай на том Python, что есть, и запиши версию. Docker-часть проверяет CI, её смотреть по логу последнего прогона на `main`.

## 1. Чистый клон

`git clone` репозитория с GitHub в новую пустую папку, не копию `~/auditenv`. Пройти README буквально, команда за командой, сверху вниз. По каждой команде записать, выполнилась ли она и совпал ли вывод с тем, что написано в README. Любое расхождение это находка.

## 2. Своя политика только по README

1. По разделу 4 README написать в новой папке вне репозитория свою минимальную политику. Не копировать пример из README, написать заново по описанию протокола.
2. Запустить её через `--policy-cmd` на одном эпизоде dev и на сгенерированном по `--config` и `--seed`.
3. Проверить то, что README обещает. Награда в конце, запись траектории, поведение при падении политики, при зависании дольше лимита, при мусоре в stdout, при неверном findings.
4. Если по README это сделать нельзя или нужно угадывать, это находка высокой важности.

## 3. Оценка инженерии по кейсу §10

Блок «Инженерия и объяснение» это пять критериев по 0, 1 или 2 балла.
- запуск одной командой
- версии конфигураций
- журналы траекторий
- измеренный разбор сбоев
- честные ограничения

По каждому поставить балл, как поставило бы жюри, с обоснованием и тем, чего не хватает до 2.

## 4. Что сдать по кейсу §09

Пройти список из кейса §09 и для каждого пункта найти его в репозитории или записать, что его нет. Исходники с лицензией и зафиксированными зависимостями, README с инструкцией контейнера и единой командой, matcher и награда, 10 train и 10 dev эпизодов, тесты, четыре адаптера базовых политик, trajectories.jsonl с полями из §09, записка о дизайне. Демо будет отдельно, его не проверять.

## 5. Числа и утверждения

- Каждое число в README и DESIGN.md сверить с `docs/METRICS.md` или с выводом команды.
- Выбрать 5 утверждений из «Известных ограничений» и DESIGN.md и проверить их командой, где это возможно.
- Абзац «Закрытый прогон жюри». Понятно ли с первого чтения, что и где запускать.
