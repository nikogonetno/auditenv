## Что сделать

```python
# auditenv/verify/__init__.py
def verify_episode(episode_dir: str, strict_volume: bool = True) -> list[dict]:
    """Список проблем вида {"code": "INV-18", "detail": "..."}. Пустой список значит эпизод корректен. Никогда не бросает исключение."""
```

CLI: `python -m auditenv.verify DIR` печатает проблемы по одной JSON-строке и выходит с кодом 1, если они есть.

Проверки по порядку важности.

1. **INV-18, главная.** Свой детектор правил INV-13…INV-16 на итоговых открытых файлах. Множество нарушений по паре (type, канонические affected_ids) совпадает с truth один к одному. Отдельно сообщать ошибки truth, которых детектор не видит, и нарушения, которых нет в truth.
2. **INV-17.** Сумма каждой ошибки пересчитывается только из записей одного набора `evidence_sets` и `policy.json` в пределах `tolerance_minor`. Проверять каждый набор.
3. **INV-01, INV-02.** Каждая проводка (`je_id`) сбалансирована, общая оборотно-сальдовая ведомость даёт ноль.
4. **INV-20 и D-4.** Каждая сумма больше двух допусков. В truth нет двух ошибок с одинаковыми type и affected_ids.
5. **INV-23.** В открытых файлах нет issue_id, названий типов ошибок и слов truth, provenance, inject, twin, scenario.
6. **INV-03.** Не меньше 10 настоящих строк соседних периодов с каждой стороны. При `strict_volume=False` пропускается, на mini_v03 их только по 2.
7. Остальные INV из списка, если останется время.
