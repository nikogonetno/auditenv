## К субботе 02.00

4. **`auditenv/config.py`.** Схема config v1 из `docs/tasks/A_generator.md`. `normalize_config(config) -> dict` подставляет значения по умолчанию. Неизвестный ключ или недопустимое значение дают `ValueError` (E-23). Порядок ключей не влияет на результат (E-16). Всего ошибок не больше 12, C1 считается за 3. `base_currency` пока только `KZT`. Схему вписать в SPEC §4.4.
5. **`env.reset(seed, config)` без `episode_dir`.** Нормализует config, вызывает `auditenv.generate.generate_episode(seed, config, tmp)` в закрытую от политики временную папку, затем грузит эпизод. `episode_dir` остаётся для готовых эпизодов и тогда запрещает остальные ключи. Пока генератора нет, тест подменяет его функцией, которая копирует mini_v03. Заглушку в рабочий код не класть.
6. **`policies/reconcile.py`, простая сверка.** Нарочно наивная, это базовая политика, а не верификатор. Листает все таблицы в пределах 100 шагов и применяет четыре прямых правила. Тот же контрагент и та же сумма AP дают дубль. Счёт, который остался открытым после платежа со ссылкой на него, даёт ошибку распределения. Курс строки не равен курсу fx на дату документа без правила выходных даёт ошибку курса. Дата по UTC вне периода даёт ошибку периода. Она должна попадаться на двойников, так и задумано. Не смотреть в код V.
7. **`scripts/stress.py`.** Для N seed генерирует эпизод, запускает V, проверяет, что oracle получает 1.0, эпизод идёт меньше 60 секунд, а два запуска с разным `PYTHONHASHSEED` дают одинаковые sha256. В `make verify` идёт с N 5, отдельно `make stress N=300`.
